# ADR 0003: AI-primary classification via Transformers.js with keyword fallback

## Status

Accepted

## Context

The hardcoded keyword matcher misclassifies emails when subject + snippet wording is ambiguous. A rejection letter was classified as `application_confirmation` because the keyword patterns overlapped. As the extension moves toward public release, classification accuracy is the core value proposition and needs to improve beyond what static patterns can deliver.

Job email classification is a narrow, well-bounded task (5 categories, ~250 chars input) that fits comfortably within on-device small model capabilities, avoiding any recurring AI API costs.

## Decision

Use a fine-tuned DistilBERT-class model (~65-80MB ONNX) running via Transformers.js in a Chrome MV3 offscreen document as the primary classifier. Keyword matching becomes a fallback, not the default.

### Classification tiers

1. **AI confidence >= 0.7** -- use the model's classification
2. **AI confidence 0.4-0.7** -- fall back to keyword matching as tiebreaker. If keywords match a category, use keywords. If keywords return `other`, use the model's answer.
3. **AI confidence < 0.4** -- classify as `other`

### Runtime architecture

- **Service worker** -- sync scheduling, Gmail API calls, message passing
- **Offscreen document** -- model loading, inference via Transformers.js, responds to classification requests from service worker

### Model delivery

- Not bundled with the extension. Downloaded from HuggingFace Hub on first use.
- Cached in IndexedDB by Transformers.js. Subsequent loads are instant from cache.
- First install flow is sequential and blocking: OAuth -> download model (with progress bar) -> scan inbox.
- Model can be updated independently of the extension by bumping the revision in code.

### Training data

- Synthetic dataset generated by a large LLM (subject + snippet pairs across all five categories)
- Validated against real classified emails from dogfooding

### Failure handling

- Model download failure: retry once, then fall back to keyword classification for this sync. Retry download on next sync cycle.
- Inference failure: fall back to keyword classification for that email. Do not block the sync.
- Keyword matching is the universal safety net for any AI-layer failure.

### Category visibility change

- `other` emails are now shown in the UI instead of being dropped. The AI classifier positively identifies job-related emails that don't fit the four main categories.
- Badge remains unchanged: only unseen `interview_request` + `offer` (per ADR 0002).

## Consequences

- Classification accuracy improves, especially for ambiguous emails where keyword patterns overlap across categories.
- Zero recurring AI cost -- all inference is on-device.
- First install adds ~20-30 seconds for model download (one-time).
- Extension depends on an external model artifact hosted on HuggingFace Hub. If the Hub is unreachable on first install, the user gets keyword-only classification until the next successful download.
- The keyword matcher is retained as fallback code, increasing maintenance surface slightly. Acceptable tradeoff for reliability.
- The offscreen document adds a new runtime component to the extension architecture.
